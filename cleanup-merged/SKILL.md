# cleanup-merged

マージが済んだ作業の、ブランチと worktree を片付けるスキル。
判定と削除は `scripts/cleanup.py`（このスキルのフォルダにある）がする。Claude は対象を決め、スクリプトを実行し、結果を伝える。

スクリプトが「消す」と判定するのは、次をすべて満たすブランチだけ。

- ブランチの先端が `origin/<既定ブランチ>` に入っている（`fetch --prune` の後で確かめる）。または、マージ済み PR の head と同じ（squash マージ）。
  PR がマージ済みでも、その後に足したコミットが入っていなければ残す。
- 本体のチェックアウト、そこで開いているブランチ、既定ブランチではない。
- worktree があれば、未コミットの変更も追跡外のファイルもない。

消すときは、worktree（`git worktree remove`、`--force` なし）→ 手元のブランチ（`git branch -D`）→ リモートのブランチ、の順。
リモートは、リモート側の先端も既定ブランチに入っているときだけ消す。

## 手順

1. 対象のブランチを決める。
   - 名前を挙げられたら、そのブランチ。
   - 「この worktree」「このブランチ」なら、`git branch --show-current` のブランチ。
   - 「マージ済みを全部」のように名前がなければ、名前を挙げずに実行する（全ブランチを調べる）。
2. 計画を出す。リポジトリの中（worktree の中でもよい）で実行する。

   ```bash
   python3 <このスキルのフォルダ>/scripts/cleanup.py [ブランチ ...]
   ```

3. 消す。
   - 手順1で名前が決まっていたら、計画の「消す」に入ったブランチを挙げて、そのまま `--yes` を付けて実行する。
   - 全ブランチを調べたときは、計画を見せて、どれを消すか本人の返事を待ってから、返事のあったブランチを挙げて `--yes` を付けて実行する。
4. 結果を伝える（下の「報告」）。

このセッションが動いている worktree を消すと、そのあとのコマンドは動かない。スクリプトはそれを最後に消すので、報告を書いてから、本人にこのセッションを閉じるよう伝える。

## 報告

消したものと残したものを、理由と一緒に表にする。

| ブランチ | 結果 | 理由 |
|---|---|---|
| `fix-foo` | worktree、手元、リモートを消した | origin/main に入っている（PR #12） |
| `wip-bar` | 残した | worktree に未コミットの変更がある |

残したブランチは、理由を伝えて、どうするかは本人に任せる。消すかどうかの判定はスクリプトに一本化している。

## うまくいかないとき

- 削除のコマンドが権限の設定で止められたら、止められたことを伝え、本人が実行できるように同じコマンドを `! ` 付きで示す。
- `gh` が使えないと、squash マージしたブランチは「マージ済みの PR もない」として残る。`gh auth status` の結果を伝える。
