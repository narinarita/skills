# herdr-pane

自分の子として Claude を起動し、ペインに出して、最初の指示を渡す。

コマンドの正しい形は `~/.config/herdr-app/AGENTS.md`（「Sub-agents」「Panes」「Terminals」「herdr-core (hc)」）、
`herdr-app commands`、`hc run --help` に従う。ここに書いた形と食い違ったら、そちらに従う。

## なぜ `pane.split` ではないか

サイドバーのツリーは、hc が記録する `parent` で親子を決める。
`herdr-app do pane.split --argv '["claude"]'` で起動すると `parent` が空になり、ツリーにならない。
そこで、先に `hc run` で起動して親（`$HC_TERMINAL_ID`）を記録させ、そのあと `terminal.keep` でペインを与える。

## 引数

- 方向: `right`（既定）か `down`
- 名前: 子の名前。英小文字・数字・`-`・`_` で 1〜32 文字。サイドバーにこの名前で出る。なければ内容から短く付ける
- 指示: 子の Claude に渡す本文。最初の指示は `hc run` に直接渡す
- フォルダ: 既定は今のフォルダ。別の worktree などで動かすときは `--cwd`

## 手順

1. 子として起動する。`--bg` を必ず付ける（付けないと、子の画面が自分の出力に流れ込み続ける）。

   ```sh
   hc run --bg --json --name <名前> --cwd <フォルダ> claude "<指示>"
   ```

   返り値の `address`（例: `t44`）を控え、`parent` が自分の `$HC_TERMINAL_ID` になっていることを確かめる。
   名前が使用中でエラーになったら、別の名前で起動し直す。

2. 子にペインを与える。自分のペインの右か下に出る。

   ```sh
   herdr-app do terminal.keep '{"terminal":"<address>","place":"right"}'
   ```

   `"pending": true` が返るのは正常。`{"error": ...}` が返ったら、内容をユーザーに伝えて止まる。

3. 最初の指示が届いたか確かめる。

   ```sh
   hc wait <address> --timeout 60
   hc read <address> --lines 30
   ```

   `claude "<指示>"` のような直接起動では、`hc get` に `first_message` が出ない（null）。
   届いたかどうかは `hc read` の画面で判断する。`first_message.sent` を見られるのはテンプレート起動のときだけ。

   届いていなければ画面を読み、trust ダイアログが出ていないか確認する。
   ダイアログは勝手に承認せず、ユーザーに確認する。解消したら `hc send <address> "<指示>"` で送る。
   届いたかどうか分からないときは、先に画面を読み、すぐには送り直さない。

4. ユーザーに、子のアドレスと名前、送った内容を伝える。

## 守ること

- 新しいペインは画面に出る。ユーザーに頼まれていないのに自分の判断で使うときは、起動する前に、何をどのペインで任せるかを1〜2行で伝えて承認を得る。頼まれたときは確認しなくてよい。
- 子は、親（自分）の Claude が終わると一緒に終わる。親より長く残したいときだけ `--outlive-parent` を付ける。
- 結果を自分に返させたいときは、指示の最後に
  「終わったら `hc send <自分のアドレス> "<要約>"` で報告して」と書く。自分のアドレスは `$HC_TERMINAL_ID`。
- 子の Claude に、さらにエージェントを起動させない。必要なときは、指示の中で明示的に許可する。
- 自分が作っていないターミナルやペインは閉じない。片付けは `hc kill <address>`（ペインも閉じる）。
- 画面に出す必要のない作業なら、手順 2 を飛ばす。子はペインなしで動き、サイドバーでは自分の下に出る。
